The agent, S14: the corner box, the column, settings

Every new part of step S14 (agent.md §4.6, §6 Phase 6), in dark and light, 1568 × 980 at 2×, on a seeded workspace ("Pazar", the evals' medium fixture imported through the app). The agent runs on the dev stub (?agentStub=1): scripted answers on the real tools, so steps, citations, the change list and the undo are real; the wording of the answers is the stub's, not a model's. Open with npx serve docs/specs/agent-shots or the dev server. Not final: the look is for the user to change.

01 the corner box

Closed: a framed box in the bottom-right corner, --space-3 from the edges like the bottom-left tools, a cyan > and ask about Pazar… (the focused plane's name in a focus), ⌘J to open (also / when nothing has the keyboard). Look at: it never covers the canvas's tools. Not final: the orb could come back here (design session).

02 open: the first asks

Focused, the box grows upward (closed it's a region; open, a dialog the keyboard is in): TRY ── and up to four asks chosen from the workspace, in Geist (the person's voice), one short mono line (changes are shown first · one undo step), the prompt. Esc gives the keyboard back to what had it. Look at: the asks name real things from this workspace.

03 the first message: the column, steps live

The first message grows the box, cell by cell (320 ms; at once with reduced motion), into a full-height column on the right; the app narrows beside it (--ai-w), so nothing is under it. Each turn is numbered (01 ──, the number magenta, D-266). Steps are live mono lines (searching "know pricing"… 8ms), a spinner per running step, [stop] in the prompt, the scope line at the foot. Not final: the canvas re-centres when it narrows (it doesn't keep its left edge yet).

04 a cited answer

When the turn ends, its steps fold to ▸ 2 steps · 3.5s (click to unfold). The answer is Geist in light Markdown; cited things read c15 "title", the id cyan, the title underlined dashed (only under the text, also when it wraps): a click or Enter goes there (the UI facade's goTo). Tokens per answer under it, no prices (56k in · 200 out, cached on hover).

05 an edit: the change list

A change writes nothing: the turn ends with the pending changes in the ledger look, 01 CHANGE ──── nothing written yet (magenta number and lead), grouped by where (SEGMENTS · PLANE), rows split by dashes, + new, − deletes (magenta, with the agent's reason), warnings in yellow, then [apply ↵] [discard esc]. The app is locked while it waits. Not final: S15 replaces this list with the real preview (the store swapped, marks on every kind, ticks, the stepper).

06 applied, with [undo]

Applied as one undo step (as the agent): the list says applied, then a status line ✓ APPLIED · 1 change · Segments [undo] ([undo] only while it's still the last step). Undone from the chat: the list says undone (struck), the line ↺ UNDONE · 1 change · Segments.

07 an error in plain words

A refused key (OpenAI's 401, answered by the test, no real call): ! your key was refused — check it in Settings → the agent with [open settings]. The header shows the chat's model switch (no stub here).

08 Settings → the agent

Under YOU: your own OpenAI key (a password field; once saved only sk-…wxyz, [check] asks OpenAI for the models it can use, [remove]), the model (works well / not tried yet; the suggested one only pre-selected), reasoning (medium), the keys (⌘J; on Windows and Linux Ctrl+J, which takes the place of the browser's Downloads shortcut), this month's usage in tokens (the dev stub's turns aren't counted). The note says where the key goes; the dev-stub note shows in dev only. Opened at a page, the keyboard is on that page's menu item.

09 beside a focused plane, the card panel left of it

In a plane's focus with a card's panel open: the right panel (D-219) sits left of the column, never under it (it reads --ai-w); beside (D-211) and the tasks side view (D-300) live inside the app's box, which narrows.

10 ≤ 760 px: the chat covers the screen

On a phone-wide window the box sits in the corner; the column then covers the whole screen (the app keeps its width under it).

11 a viewer

A viewer opens the same agent: it reads and answers, and says it changes nothing. A viewer's agent has no change tool at all and is told up front it only reads, so asked for a change it says an editor can make it (the wording here is the dev stub's).

12 the agent's marks (local presence)

While a turn runs, what the agent reads gets its marks the way others' selections are drawn (D-272): cyan L's round it and a tag agent · reading outside its top edge at the right end (clear of a piece's name), magenta while changing; only on something truly visible (the point at its middle must hit it), gliding from thing to thing, gone 2.5 s after the turn. Only you see it for now: showing it to others needs a presence rule. Not final: the user may want a cursor too.

13 about 1100 px wide: clear of the focus dock

The box narrows with the window (clamp round the bottom's middle), so on a ~1100 px window it stays clear of the focus dock, closed and open.

14 not shown here

Reduced motion was checked in the browser: the column appears at once (no cell build), spinners hold still as …, the caret doesn't blink, the marks don't glide. Keyboard: what had focus before the agent opened gets it back on ⌘J, Esc or [×]; after [stop] the keyboard is back in the prompt; / does nothing while a list or menu is open.
